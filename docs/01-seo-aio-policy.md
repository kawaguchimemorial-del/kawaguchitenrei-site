# 01. SEO / AIO 方針

このファイルは、kawaguchitenrei.com の SEO（検索エンジン最適化）および AIO
（AI 検索・生成 AI 回答最適化）方針を定める。

実装時の判断軸は `CLAUDE.md` §10、文言ルールは `docs/05-content-guidelines.md`、
評価は `docs/eval/seo-aio-checklist.md` を参照。

---

## 1. SEO の基本方針

### 1.1 戦略

- **地域 × サービス語** のロングテールを丁寧に取る
  - 例：「川口 家族葬」「鳩ヶ谷 葬儀」「めぐりの森 葬儀」
- 大手ポータルが薄い「**自社式場での実体験**」を厚く書く
- **E-E-A-T**（経験・専門性・権威性・信頼性）を重視
  - 創業20年、年間約260件の実績
  - 自社式場「川口メモリアルホール」
  - 川口市の葬祭事業登録業者
- **YMYL 領域**（人の生死・お金に関わる）なので、**断定・煽りを避ける**

### 1.2 やらないこと

- キーワード詰め込み・連呼
- 内容のないドアウェイページ量産
- 他社サイト文章のコピー
- 「絶対」「必ず」「最安保証」など断定表現
- 不安を煽る誘導文

## 2. AIO（AI 検索・生成 AI）への対応方針

ChatGPT・Google AI Overview・Perplexity・Gemini など、生成 AI が情報源として
ページを参照・引用しやすい構造に整える。

### 2.1 AIO で効く要素

| 要素 | 理由 |
|---|---|
| **結論先出し** | 冒頭の 1〜2 段落で要点が分かる |
| **基本情報表** | 所在地・電話・対応形式・営業時間など、AI が抽出しやすい |
| **FAQ** | 質問 → 回答の構造を AI が学習・引用しやすい |
| **構造化データ（JSON-LD）** | LocalBusiness / FuneralHome / FAQPage / Breadcrumb |
| **見出し階層の整合** | h1 → h2 → h3 が論理的に並ぶ |
| **箇条書き** | 短文・並列の情報は AI が再構成しやすい |
| **明確な数値** | 「車で約5分」「駐車場70台」「年間約260件」など |
| **URL の命名** | `/saijo/megurinomori/` のように内容が分かる |

### 2.2 各ページに最低限置くもの

- **冒頭の結論ボックス**（1〜2 段落）
- **基本情報表**（住所・電話・対応形式など、ページ性質に応じて）
- **FAQ**（3〜6 個程度）
- **構造化データ**（該当タイプ）

## 4. ページ種別ごとの SEO 方針

### 4.1 トップページ（`/`）

| 項目 | 方針 |
|---|---|
| title | 川口典礼 / 川口市・新井宿の葬儀・家族葬 / 川口メモリアルホール 等を 60 字以内 |
| description | 地域密着・自社式場・めぐりの森近接・24時間365日・実績を 120 字程度 |
| h1 | 屋号 + 地域 + 自社式場の核訴求（1 行で完結） |
| h2 構造 | プラン / ホール / めぐりの森 / 施工事例 / 口コミ / FAQ / エリア / アクセス / CTA |
| 内部リンク | プラン詳細・ホール詳細・エリア・FAQ・施工事例へ漏れなく |
| 構造化データ | `FuneralHome` / `BreadcrumbList` |
| FAQ | 3〜6 個（料金・対応エリア・24時間対応・事前相談など） |

### 4.2 プランページ（`/plan/<slug>/`）

| 項目 | 方針 |
|---|---|
| title | プラン名 + 価格 + 川口典礼 |
| description | プランの「向いている方」「日数」「人数」「価格」を端的に |
| h1 | プラン名（短く） |
| 結論ボックス | 「○○な方向け」「価格目安」「日数」「人数」 |
| 内部リンク | 利用できる斎場（`/saijo/`）、川口メモリアルホール、他プラン |
| 構造化データ | `Service` / `Offer` / `FAQPage` / `BreadcrumbList` |
| FAQ | 3〜6 個 |

### 4.3 斎場一覧（`/saijo/`）

| 項目 | 方針 |
|---|---|
| title | 川口市・近隣の葬儀場一覧 / 川口典礼 |
| description | 自社式場 + めぐりの森 + 戸田 + 谷塚 + 寺院会館で網羅 |
| h1 | 川口市・近隣で利用できる葬儀場一覧 |
| h2 | 自社式場 → 公営斎場 → 寺院会館・民営式場 → 選び方 → FAQ |
| 内部リンク | 自社式場 / 各斎場詳細 / プラン |
| 構造化データ | `BreadcrumbList` / `FAQPage` |

### 4.4 斎場詳細（`/saijo/<slug>/`）

| 項目 | 方針 |
|---|---|
| title | 斎場名 + 種別（火葬場 / 火葬場併設斎場）+ 川口典礼 |
| description | 所在地・利用条件・川口典礼での対応 |
| h1 | 斎場名 + 葬儀・火葬のご相談 |
| 結論 | 川口典礼が運営する施設ではないこと、相談・手配に対応していることを明記 |
| 構造化データ | `Place` / `BreadcrumbList` / `FAQPage` |

### 4.5 川口メモリアルホール（`/hall/kawaguchi-memorial-hall/`）

| 項目 | 方針 |
|---|---|
| title | 川口メモリアルホール / 川口典礼の自社ホール |
| h1 | ホール名 + 川口市西新井宿の自社式場 |
| 訴求 | 駐車場70台、めぐりの森まで車で約5分、家族葬〜200名、個室面会室 |
| 構造化データ | `FuneralHome` / `BreadcrumbList` / `FAQPage` |

### 4.6 めぐりの森関連（`/saijo/megurinomori/`、横断導線）

- 「めぐりの森 葬儀」「川口市めぐりの森 葬儀」を意識
- ホール側ページからも「車で約5分」を繰り返す
- 川口市営の火葬場であり、川口典礼の運営施設ではないことを明記
- 施設の利用相談・手配は川口典礼が対応する旨を明確化

### 4.7 エリアページ（`/area/<slug>/`）

| 項目 | 方針 |
|---|---|
| title | <地域名> 葬儀・家族葬 / 川口典礼 |
| h1 | <地域名> の葬儀をお手伝い |
| h2 | 地域の葬儀傾向 → プラン → よく利用される斎場 → 選ばれる理由 → 流れ → FAQ |
| 内部リンク | プラン・ホール・斎場・FAQ |
| 構造化データ | `BreadcrumbList` / `FAQPage`、可能なら `Service` の `areaServed` 指定 |

### 4.8 施工事例（`/case/<slug>/`）

- 個人情報を出さない（地域名は町名程度まで、宗派は粒度を抑える）
- 「人数 / 日数 / 形式 / 斎場 / 概算費用」の表形式
- 「ご家族の声」を 1〜2 段落で添える
- 構造化データ：`Article`（`author` は法人名）

### 4.9 口コミ（`/voice/<slug>/`）

- 喪主名・故人名を出さない（イニシャル・年代・地域まで）
- 一字一句の創作はしない。事実ベース。
- 構造化データ：`Review`（`itemReviewed` は法人 / ホール）
- 口コミは「形式 → 価格帯 → 印象」で分類できる構造を検討

### 4.10 FAQ（`/faq/`）

- ページ全体で 20〜40 個程度を目安に拡充
- 「料金」「対応エリア」「斎場」「宗派」「事前相談」「市民葬」「直葬」などカテゴリで整理
- 構造化データ：`FAQPage`

### 4.11 コラム（`/column/<slug>/`）

- 検索意図ごとに 1 本にまとめる
- 結論先出し、見出し階層整合、FAQ ブロック
- 構造化データ：`Article` / `BreadcrumbList`、必要なら `FAQPage`

## 5. title / description / h1 / h2 の方針

### 5.1 title

- 全角 30 字以内（半角 60 字以内）を目安
- 「主訴求 + 地域 + 屋号」の順を基本に
- 「｜」または「 / 」で区切る
- 文末に屋号「川口典礼」を入れる

### 5.2 description

- 全角 60〜80 字、最長 100 字程度
- 結論を先に書く（「川口市の家族葬は…」のような）
- 数字を入れる（「駐車場70台」「車で約5分」「年間約260件」など）
- CTA 的な文末は控えめ（「ご相談ください」程度）

### 5.3 h1

- 1 ページ 1 つ
- 短く・主訴求 1 件に絞る
- 地名 + サービス語を入れる

### 5.4 h2 / h3

- 章立てとして論理的に並ぶこと（AIO で重要）
- h2 の中に h3、h3 の中に h4 という階層を飛ばさない
- 「FAQ」「アクセス」「料金」「対応プラン」など定番ブロックは命名を統一

## 6. 内部リンクの方針

### 6.1 リンク先優先度

| 種類 | 優先度 |
|---|---|
| プラン詳細 | 高 |
| 川口メモリアルホール詳細 | 高 |
| めぐりの森詳細 | 高 |
| 斎場一覧（`/saijo/`） | 高 |
| エリアページ | 中 |
| 施工事例 | 中 |
| FAQ | 中 |
| 口コミ | 中 |
| コラム | 低 |
| legal pages | 低 |

### 6.2 リンク文言

- 「こちら」「詳しくはこちら」は使わない
- リンク文言にキーワードを含める（「川口市めぐりの森の葬儀案内」「家族葬プランの詳細」）
- パンくず（`BreadcrumbList`）を全ページに

## 7. 構造化データの方針

採用候補（実装は段階的に）：

| 種類 | 利用ページ | メモ |
|---|---|---|
| `FuneralHome` | トップ、ホール詳細 | 法人・自社式場の主要情報 |
| `LocalBusiness` | 補助的に | 営業時間・住所など |
| `Place` | 斎場詳細 | 公営斎場・他社斎場 |
| `BreadcrumbList` | 全下層ページ | 必須 |
| `FAQPage` | FAQ・FAQブロックがある全ページ | 必須 |
| `Article` | コラム・施工事例 | `author` は法人名 |
| `Review` / `AggregateRating` | 口コミ | 個人特定を避ける |
| `Service` | プラン詳細 | `areaServed` を指定 |

実装ルール：
- JSON-LD は `dangerouslySetInnerHTML` ではなく `<script type="application/ld+json">` で安全に出力
- `@id` を入れてエンティティを繋ぐ（同一法人の `FuneralHome` には全ページで同じ `@id`）
- 嘘・誇張は書かない（人数・実績・営業時間は事実のみ）

## 8. AIO 向け：表・FAQ・結論ボックス・基本情報表

### 8.1 結論ボックス（冒頭）

各ページの h1 直下に、2〜3 行で要点を書く。

例（プランページ）：
> 一日葬は、お通夜を行わず告別式と火葬を 1 日で行う葬儀形式です。
> 川口典礼の一日葬プランは事前相談会員価格 396,000 円（税込）から。
> 川口市めぐりの森での火葬まで一貫してお手伝いします。

### 8.2 基本情報表

各斎場・ホールページに、AI が抽出しやすい表を置く。

例：
| 項目 | 内容 |
|---|---|
| 所在地 | 埼玉県川口市西新井宿440-1 |
| 駐車場 | 70 台 |
| 火葬場まで | 川口市めぐりの森まで車で約 5 分 |
| 対応形式 | 家族葬・一日葬・直葬 |

### 8.3 FAQ ブロック

- 各ページに 3〜6 個
- 質問は検索クエリに近い文体（「○○はできますか？」「○○の費用はいくらですか？」）
- 回答は結論 → 補足 → 確認導線（「正式なお見積り時に確認」など）

## 9. 「最安」ではなく「地域密着・自社式場・近接性・透明性」で勝つ

価格訴求では大手ポータルに勝てない。次の軸で勝つ：

1. **地域密着**：川口市・新井宿に根ざした 20 年の運営
2. **自社式場**：川口メモリアルホールという物理的な拠点
3. **火葬場近接**：めぐりの森まで車で約 5 分
4. **費用の透明性**：会員価格・通常価格を併記、追加費用要素を明示
5. **24 時間 365 日対応**：搬送・安置・式手配を切れ目なく

> 「最安」「絶対」「必ず」を使わない。
> 価格は「目安」と「正式なお見積りで確認」を併記。
