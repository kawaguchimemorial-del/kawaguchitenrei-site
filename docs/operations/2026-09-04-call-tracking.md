# 電話着信の記録運用（2026-09-04 開始）

- **目的**：フォームの件数だけでは、深夜帯も広告も正しく評価できない。電話を数字にして、広告・SEO の判断材料にする
- **背景**：`docs/reports/2026-09-02-ads-august-monthly-10expert.html` の「当社の宿題」
- **記録フォーマット**：[`call-log/call-log-template.csv`](./call-log/call-log-template.csv)
- **集計スクリプト**：`scripts/analyze-calls.mjs`

---

## 1. いま測れているもの／測れていないもの

サイト側の計測（GA4）は既に入っている。8月の実測は下記のとおり。

### 測れている：サイト上の「電話ボタンのタップ」＝ `click_tel`

| 項目 | 2026年8月の実測 |
|---|---|
| タップ数 | **33件**（キーイベントとして計測済み） |
| 時間帯 | 6〜11時 11件／12〜17時 21件／18〜23時 1件／**0〜5時 0件** |
| 参照元 | google/organic 15、**chatgpt.com 9**、direct 3、docomo 3、bing 2、yahoo 1 |
| ページ | トップ 16、/plan/ 8、/hall/ 6、/plan/hanaire-owakare/ 2、/access/ 1 |

### 測れていない：3つ

1. **タップした後、実際に通話になったか**
   タップ＝発信画面が開いただけ。かけ直した／やめた／話し中だった、は分からない
2. **サイトを経由しない電話**
   役所・病院で受け取った案内、チラシ、紹介、以前のご利用。**川口で最も多い問い合わせの流れがここに入る**
3. **広告からの電話**
   広告の着地先は現在 `kawaguchi-memorial-hall.com` で当社の計測外。8月の `click_tel` に google/cpc は**0件**だが、これは「広告から電話がない」ではなく「見えていない」

> **この3つは、電話を受けた人が記録する以外に埋める方法がない。** それが本運用の目的。

## 2. 記録のしかた

### 2.1 記録する場所

`call-log/` に月ごとの CSV を置く。ファイル名は `calls-YYYYMM.csv`（例：`calls-202609.csv`）。
テンプレートをコピーして使う。Excel でも Google スプレッドシートでもよい。

### 2.2 記録する項目

| 列 | 内容 | 選択肢 |
|---|---|---|
| `date` | 日付 | `2026-09-04` の形式 |
| `hour` | 時刻（時のみ） | `0`〜`23`。9時35分なら `9` |
| `type` | 種別 | `着信` / `発信` |
| `purpose` | 用件 | `相談` / `依頼` / `参列者` / `営業` / `その他` |
| `origin` | きっかけ | `不明` / `ネット検索` / `広告` / `役所・病院の案内` / `紹介` / `チラシ` / `以前利用` |
| `result` | その後 | `施行` / `見積のみ` / `検討中` / `対象外` / `未定` |
| `note` | メモ | 任意。**個人が特定できることは書かない** |

### 2.3 ぜったいに書かないこと（CLAUDE.md §12）

- お名前・故人様のお名前・喪主様のお名前
- 電話番号・住所・メールアドレス
- 具体的な日程（ご葬儀の日付など、個人が特定できる情報）

**この CSV は、件数を数えるためのものです。** 誰からの電話だったかを残す台帳ではありません。
お客様の情報は従来どおりの管理方法で扱ってください。

### 2.4 `origin`（きっかけ）の聞き方

無理に聞き出さない。会話の流れで分かった範囲で構わない。分からなければ `不明` でよい。
`不明` が多くても、**時間帯と件数だけで十分に価値がある**（深夜に何件あるかが分かる）。

参考の聞き方：「差し支えなければ、当社をどちらでお知りになりましたか」

## 3. 集計のしかた

CSV を置いたら、次のコマンドで集計する。

```
node scripts/analyze-calls.mjs docs/operations/call-log/calls-202609.csv
```

出力されるもの：

- 時間帯別の着信件数（深夜帯に何件あるか）
- きっかけ別の件数（広告・役所案内・ネット検索の比率）
- 用件別の件数（相談／依頼／参列者の比率）
- **同じ月の GA4 `click_tel` との突き合わせ**（サイト経由がどれくらいか）
- 施行につながった件数

`--ga4` を付けると GA4 から `click_tel` を取得して並べて表示する。

```
node --env-file=.env.local scripts/analyze-calls.mjs docs/operations/call-log/calls-202609.csv --ga4
```

## 4. この記録で答えられるようになること

| いま答えられない問い | 記録があれば |
|---|---|
| 深夜0〜5時の広告は成果につながっているか | 深夜の着信件数で判断できる。件数0なら深夜配信を見直す材料になる |
| 広告と自然検索、どちらが電話を生んでいるか | `origin` の比率で分かる |
| 役所・病院の案内からの流入はどれくらいか | `origin`＝`役所・病院の案内` の件数 |
| 参列者の電話にどれだけ時間を取られているか | `purpose`＝`参列者` の件数。指名広告の判断材料になる |
| サイトの `click_tel` は実際の電話とどれくらい一致するか | 両者を並べて比率が出る |

## 5. 運用のコツ

- **毎日つけようとしない。** 手が空いたときにまとめて入れてよい。ただし当日中か翌日には入れる
- **1本1行。** 折り返しの発信も `発信` として記録すると、往復が見える
- **迷ったら記録する。** 営業電話も `営業` として入れておくと、実需要との差が分かる
- **月末にスクリプトを流して、レポートに添える。** 広告の月次レポートと同じタイミングが扱いやすい

---

## 6. 3か月後に見直すこと

この運用は、続かなければ意味がない。2026年12月時点で以下を確認する。

- 記録の抜けが多すぎないか（月の着信件数が実感と合っているか）
- `origin` の `不明` が9割を超えていないか（超えていたら聞き方を変えるか、`origin` を諦めて件数だけにする）
- 記録が実際に判断に使われたか（使われていないなら、項目を減らす）

**項目を増やす方向の見直しはしない。** 続けられる形に削る方向でのみ見直す。
