Search Console 重大な問題の対応（404×5・リダイレクトエラー×5・重複×1）

作成日：2026-06-12対象データ：GSC Coverage 2026-06-12 エクスポート担当：Claude Code

社内記録（Web非公開・noindex）。個人情報・秘密情報なし。

背景：Search Console の「ページのインデックス登録」で重大な問題として 404×5・リダイレクトエラー×5 等が報告された。本対応では 404 の5件（URLエクスポート取得済み）を精査し、転送先が明確なものへ 301 を追加した。

1. 事前検査（リダイレクト設定の健全性）

  • 既存リダイレクト 187 件：チェーン・ループ 0 件。
  • 転送先 64 種すべてが実在ページ（column / voice / case / plan のスラッグと一致）。リンク切れの転送先なし。
  • sitemap は data 駆動で、列挙 URL は全てルートが存在。

→ 設定内部に起因する 404／リダイレクトエラーは無し。404 は sitemap 外の旧URL（外部にインデックス済みの過去URL）が原因と判断。

2. 404 の5件と判定

旧URL最終クロール判定・対応
/SK/022026-06-01301 → /（内容特定不可・トップ集約。ユーザー確認済み）
/SK/032026-05-31301 → /（同上）
/maisouhi2026-06-01301 → /column/sousaihi/（葬祭費コラム。ユーザー確認済み）
/plank2025-12-11対応不要：既に /plank → /plan/ 設定済み。古いクロール残骸で再クロールにより解消見込み
/★このページのスラッグ2026-05-24対応不要：旧CMSのテンプレ消し忘れ。実在すべきでないURLのため 404 のまま正解（無関係ページへの転送はしない）

3. 変更内容（next.config.ts・6エントリ追加）

  • /SK/02 ・ /SK/02/ → /
  • /SK/03 ・ /SK/03/ → /
  • /maisouhi ・ /maisouhi/ → /column/sousaihi/

既存パターンに合わせ、末尾スラッシュ有無の両方を permanent: true（301）で追加。

4. 確認結果

  • npm run build：✓ 成功・コンパイル成功・型／警告エラーなし。
  • 静的生成 135 ページ維持（リダイレクト追加のためページ数は不変）。
  • 変更ファイル：next.config.ts のみ。

URL一覧取得後、現在の本番挙動を curl で実測。全て正常で、GSCのデータは刷新直後（クロール 2026-05-21〜26）の古い記録（stale）と判明。

6. 重複（正規未選択）×1 の対応

対象 /Column_list/nenmastu。実測で 3ホップのチェーンを経て /column/nenmastu/（実在の年末年始コラム）へ301。受け皿ページの canonical は 自己参照で正しく設定済み（/column/nenmastu/・/column/2026s_sougi/ とも）。

  • catch-all（/Column_list/:slug*）経由で遠回りになっていたため、明示の1:1 301を catch-all の前に追加し 3ホップ→2ホップに短縮。Googleへ明確な統合シグナルを送る（06-09「1対1 301」方針に準拠）。
  • 追加：/Column_list/nenmastu ・ /Column_list/nenmastu/ → /column/nenmastu/

canonical は既に正しいため、Googleの再処理で /column/nenmastu/ に統合される見込み。今回の追加はチェーン短縮による補強。
