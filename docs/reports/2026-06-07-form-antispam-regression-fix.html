【緊急修正】フォーム送信が届かない不具合（迷惑送信対策のリグレッション）

作成日：2026-06-07 担当：Claude Code

社内記録（Web非公開・noindex）。個人情報・秘密情報なし。関連：迷惑送信対策（初回実装）。

不具合：迷惑送信対策（コミット 0276ef8）の導入後、実フォームの送信で「送信できました」と表示されるのに、メール送信・GAS保存がされない事象が発生。ユーザー報告で判明。

原因：bot 判定（ハニーポット／滞在時間）が本物の送信を誤検知し、「成功画面は表示するが Webhook には送らず静かに破棄」する設計だったため。誤検知の主因はハニーポット項目名 company_url がブラウザ自動入力に拾われた可能性が高い。

1. 修正方針（設計の是正）

葬儀社サイトでご遺族の本物の問い合わせを失うことは絶対に避けるべき（§8）。よって「ブロック（握り潰し）」を完全に廃止し、次の設計に是正：

  • 必ず Webhook へ届ける（bot/営業と判定しても破棄しない）。
  • bot/営業らしさは フラグ（botFlagged/botReasons/spamFlagged/spamScore）として payload に付与するのみ。
  • 実際の仕分け（通知の出し分け・別シート移動）はGAS／スプレッドシート側（＝送信後の安全な場所）で行う。
  • ハニーポット名を company_url → contact_reference に変更し、data-lpignore 等で自動入力を抑止（誤フラグの低減）。

2. 変更ファイル

ファイル内容
lib/forms/antispam.tsisBotSubmission()（boolean破棄判定）を削除し、assessBot()（フラグ評価）に置換。ハニーポット名変更。
app/contact/actions.ts / app/estimate/actions.ts先頭の「bot静かに破棄」分岐を撤去。常に Webhook 送信し、payload に ...bot, ...spam を付与。
components/forms/SpamGuardFields.tsxハニーポットに data-lpignore/data-1p-ignore を追加。

3. 確認結果

  • npm run build：✓ Compiled successfully、135ページ維持、型エラーなし、isBotSubmission 残存なし。
  • これ以降、contact / estimate は判定結果にかかわらず必ず Webhook へ送信（成功画面表示）。誤検知でも問い合わせは失われない。
  • 個人情報ログ出力なし／env非接触／Webhook直書きなし／honeypot・elapsed は payload 非混入のまま。

4. 今後

  1. 本番反映後、ユーザーに再送信テストを依頼し、メール／GAS に届くこと、payload にフラグが付くことを確認。
  2. 迷惑送信の仕分けは GAS 側で実装（botFlagged/spamFlagged で別シート移動・通知抑制）。必要なら Apps Script のサンプルを提供。
  3. ハードブロックが必要なら Tier3（Turnstile）を別途検討。ただし「届かない」リスクを伴うため、まずは GAS 側仕分けを推奨。
