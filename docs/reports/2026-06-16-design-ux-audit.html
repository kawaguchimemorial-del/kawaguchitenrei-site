デザイン/UX 監査：現状の弱点マップと優先度（モバイルファースト）

作成日：2026-06-16対象：サイト全体（ホーム＋各テンプレート）担当：Claude Code

外部Web会社からの「SEOには優しいがレイアウト/デザインはまだまだ」という指摘を受け、改善の出発点として現状を棚卸ししたもの。個人情報・秘密情報なし。

総評：土台は「素人仕事」ではない。デザイントークン（紙色2段＋深緑3段＋金の差し色＋緊急レッド／墨3階調）、明朝×ゴシックの使い分け、prefers-reduced-motion 対応、グローバルな :focus-visible 指定（globals.css 85–91行）まで揃っている。指摘の「まだまだ」は土台の崩壊ではなく、最後の1〜2割の詰め＝アイコン・タイポの統一・写真の質・セクションの緩急に集約される。本監査はそこを優先度づけする。

0. 前提・進め方

  • 既存トーンは維持（落ち着き・余白・読み物寄り）。コンセプトの作り替えはしない（CLAUDE.md §3）。
  • 6/26 の SEO 効果測定までは構造（URL / title / canonical / ページ構成）に触れない。本監査の対象は「見た目・操作感」で、構造を動かさない範囲＝SEO 再評価に影響しない改善に絞る。
  • 共通レイアウト（Header / Footer / MobileBottomCTA）は保護対象（CLAUDE.md §5）。ここへの変更提案は実装前に承認を取る。
  • 1ページ／1テーマずつ、具体案を見比べて合意 → 実装の順で進める。

2. P1（高効果・低リスク・すぐ着手可）

A. 絵文字アイコン → 実アイコン(SVG)へ統一　最有力の第一手

現状、UIアイコンに OS 依存の絵文字／記号をそのまま使っている。字形が端末でバラつき、最も「安く・素人っぽく」見える原因。

記号使用箇所（例）用途
☎Hero / Emergency / FinalCta / Header / MobileBottomCTA電話CTA
✓Hero 信頼ポイント / Plan・Saijo 詳細チェック
→ › ↗各CTA・エリアタグ・外部リンク（3種混在）遷移の矢印
★Voices 星評価レーティング
✎ ×　☰MobileBottomCTA / Header メニュー編集・閉じる・ハンバーガー（※共通chrome＝承認要）

方針：依存追加なしのインラインSVGアイコン（電話・チェック・矢印・星・外部リンク）を components/common/icons/ に小さく用意し、絵文字を置換。矢印は「主CTA＝→／カテゴリ＝chevron」と役割を1本化し、装飾の矢印は減らす。共通chrome（Header/Mobile CTA）の絵文字だけは保護対象なので別途承認を取る。

SEO/構造への影響なし。まず公開ページ側（Hero など非保護の home セクション）から着手すれば自走可。

B. タイポのスケール統一

セクション見出しのサイズが揃っていない（多くは text-3xl md:text-[2.4rem] だが、ThreeStrengths/AdvanceConsult は text-2xl md:text-[2.2rem]、MediaLinks は text-lg md:text-xl）。意図的な階層なら良いが、現状は「なんとなくバラついている」印象を与え、全体の整い感を損ねている。

方針：見出しの段階を定義（例：セクションh2＝統一サイズ／補助セクション＝1段下）。本文の行間・字間（既に leading-9〜10・palt あり）と合わせ、ジャンプ率の基準を1枚決めて全セクションに適用。

C. 星評価のSVGコンポーネント化

Voices の星は "★".repeat() ＋半透明星でのグリフ連打。半端な星の表現が崩れやすく、金色×紙色で沈む。SVG の★コンポーネント（満/半/空）に置換すると精度と見栄えが両立。Aと同時にやるのが自然。

3. P2（やや判断を伴う／中効果）

D. コントラスト・可読性

淡色テキストや極小文字に、WCAG AA 観点で弱い箇所がある（候補）。実測して必要分だけ詰める。

  • Footer の text-white/70・text-white/65（bg-deep 上）
  • Header サブ見出しの text-[11px]（モバイルで小さい）
  • Breadcrumbs / 補足の text-ink-soft

Footer/Header は保護対象のため、変更は承認後。Breadcrumbs 等の共通外コンポーネントは自走可。

E. プレースホルダー画像の鎮静化

写真未設定時の斜線ストライプ（repeating-linear-gradient(135deg …)：Cases・AreaDetail のプラン枠）が主張しすぎて「未完成」に見える。bg-warm 等の無地＋小さなロゴ/キャプションに置換し、写真が入るまでの見栄えを底上げ。

F. 自動マーキー（Cases / Voices）の速度・操作性

animation: marquee 150s linear は遅く、ユーザーが多様な事例/声に到達しにくい。ホバー一時停止はあるがモバイルで効かない。方針：速度を体感に合う水準へ調整し、モバイルはスワイプで送れる導線を検討（「すべて見る」への動線は維持）。prefers-reduced-motion 時の静止は現状維持。

G. セクションの「緩急」（背景リズム・余白）

14セクションの縦積みで、背景が paper / warm / white / cool / deep と切り替わる。cool（Cost・Access）や deep（Final CTA）は意図的なアクセントとして妥当だが、現状は切替の「理由」がユーザーに伝わりにくく、単調 or 唐突のどちらにも振れる。方針：「読み物の章＝paper/white」「情報枠＝warm」「締め＝deep」のように背景の意味を1枚に定義し、余白スケール（py-14/16/24 の混在）も段階を決めて適用。複数セクション横断のため、方針合意のうえで着手。

※調査の過程で出た「cool/deep は壊れている」「Final CTA の深緑は葬儀に不向き」という評価は採用しない。深緑はブランド色で、締めのアクセントとして妥当と判断。

4. P3（後回し or 素材準備が前提）

  • H. 写真の質：合成のFV画像（外観＋祭壇の合成 .png）、式場ギャラリーの質とキャプション。葬儀社は写真の信頼感が大きい。差し替え素材の準備が前提（人間確認必須・§13）。
  • I. 非対称グリッド比：md:grid-cols-[0.95fr_1.05fr] 等は user 体感への影響はほぼ無い。気づいた時に 1fr_1fr へ整える程度で良い（単独タスク化は不要）。

5. 良い点（壊さないもの）

  • デザイントークン・明朝/ゴシックの使い分け・控えめなモーション設計
  • テンプレート間の一貫性（見出し階層・eyebrowラベル・py-16/24・max-w-6xl・カードのhover）
  • モバイル下部CTA：safe-area対応・適切な z 順・電話/事前相談の2択（§4 準拠）
  • テーブルの overflow-x-auto、scroll-mt-24 によるアンカーオフセットなどの実装的な気配り

推奨の着手順：A（アイコンSVG化）→ C（星）→ B（タイポ統一） を最初のひとかたまりで（いずれも低リスク・SEO無影響・自走可）。次に E・F・D（共通chrome以外）、その後 G を方針合意のうえで。H は素材準備、I はついで対応。共通chrome（Header/Footer/Mobile CTA）に関わる分は都度承認を取る。

6. 次アクション

  • 合意待ち 着手順（上記推奨でよいか）と、最初の対象ページ（ホーム想定）。
  • 準備 A 着手時、SVGアイコンの線の太さ・サイズ感の方向性をサンプルで提示し、見比べて決定。
  • 維持 6/26 までは構造（URL/title/canonical）に触れない。デザイン改修は見た目のみに限定。
