状態：push 未実施（人間承認待ち）。Review/reviewRating は CLAUDE.md §19.2 により push 前に人間承認が必要。実装と npm run build まで進めた。

1. サマリ

  • 完了 各 voice 詳細ページに個別 Review JSON-LD を追加（lib/voices.ts の rating 1-5 を使用）。
  • 完了 aggregateRating はサイトに出していない（個別 Review のみ）。author は匿名「ご利用者」（個人名・故人名・喪主名なし／§12）。
  • 完了 npm run build 成功・135ページ維持。生成HTMLで Review 出力を確認。
  • 承認待ち push は人間承認後。下記「留意点」も併せてご判断ください。

2. 変更内容（app/voice/[slug]/page.tsx）

  • buildVoiceJsonLd に review を追加し、既存の BreadcrumbList・Article と並べて3つ目の JSON-LD として出力。
  • itemReviewed＝FuneralHome（川口典礼／住所・電話）。reviewRating＝Rating（ratingValue＝各 voice の rating、bestRating 5 / worstRating 1）。author＝Person「ご利用者」（匿名）。name＝感想タイトル、reviewBody＝感想本文、datePublished＝公開日。
  • lib/voices.ts は読み取りのみ（変更なし）。

4. 留意点（承認判断のため）

Google の「自社サイト上の自社レビュー」ポリシーに注意。Google は、自サイトに掲載した自社（自組織）に対するレビューのマークアップをリッチリザルト（星）表示の対象外とする方針で、運用次第ではスパム的とみなされ得ます。本実装は事実に基づく実アンケートの構造化ですが、星のリッチリザルトが表示されない可能性が高い点・将来的なポリシー解釈リスクをご了承のうえ承認ください。

  • 本案は aggregateRating をサイト全体に出していない（個別ページの Review のみ）。総合評価の集計表示は、件数・実在性・ポリシーの観点からさらに慎重な判断が必要なため見送り。
  • author は匿名「ご利用者」。個人名・故人名・喪主名は一切含めない（§12）。
  • もし星表示を狙わず「AIに引用されやすい構造化」目的に限定するなら本案は有効。逆にリスクを避けたい場合は Review も付けない判断もあり得る（その場合この変更を破棄）。
