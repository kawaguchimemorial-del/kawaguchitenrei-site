事象：お問い合わせフォームから、氏名・フリガナ・希望連絡時間帯・本文のすべてが無意味なランダム英字列（例：20文字前後の大小混在アルファベット）で構成された自動送信が届いた。実在しない連絡先が入っており、対応価値はゼロ。

原因：既存の迷惑送信対策（ハニーポット・滞在秒数・営業キーワード）は「フラグを付けるが必ず送信する」設計であり、かつ今回の内容は既存ヒューリスティクスのどれにも当たらず spamScore 0（＝検知すらできていない）だった。本文が16文字と短く、「日本語なし」判定の閾値（20文字超）を下回っていたため。

2. 設計方針（2026-06-07 の障害を踏まえて）

2026-06-07 に「bot 判定で実ユーザーの送信を握り潰す」設計が原因の障害を起こしている（ブラウザ自動入力がハニーポットを埋めた）。今回はその教訓を踏まえ、破棄する条件を「日本語話者の実入力では絶対に発生しない signal」に限定した。

signal今回の扱い理由
ハニーポット混入フラグのみ（従来どおり・破棄しない）自動入力による誤検知の実績があるため、破棄条件に復活させない
滞在秒数が短すぎるフラグのみ（従来どおり・破棄しない）単独では bot 確定と言えない
営業キーワード・URLフラグのみ（従来どおり・破棄しない）人間の営業メールは仕分け対象であって破棄対象ではない
ランダム英字列破棄日本語話者の氏名・フリガナ・本文では発生しない
Vercel BotID の bot 判定破棄（判定失敗時は人間扱いの fail-open）Vercel 純正の invisible 検知。ユーザーに CAPTCHA 等の負担を与えない

破棄時も画面上は通常どおりの完了表示を返す（bot に「弾かれた」と気付かせ、手口を変えさせないため）。

3. ランダム文字列判定のロジック

誤検知を避けるため、次をすべて満たすトークンのみ「ランダム」と判定する（lib/forms/antispam.ts の looksRandomToken）。

  1. 8文字以上の連続した英字のみ（数字・記号・空白・日本語を含まない）
  2. 母音比率が 35% 未満（自然言語の英単語・ローマ字表記は通常 35% 以上）
  3. 先頭以外に大文字が2つ以上（人が書く語・氏名は先頭のみ大文字）

氏名・フリガナ・希望連絡時間帯・本文の4項目を走査し、1つでも該当すれば破棄する。

4. Vercel BotID の構成

層内容
設定next.config.ts を withBotId() でラップ（検証用プロキシの rewrite が追加される）
クライアントinstrumentation-client.ts で initBotId()。保護対象は /contact・/estimate の POST（trailingSlash: true のため末尾スラッシュ有無の両方を登録）
サーバーlib/forms/botid.ts の isBotSubmission()。checkBotId() が例外を投げた場合は必ず false（人間扱い）を返す fail-open 設計

※ ローカル開発（NODE_ENV !== "production"）では BotID は既定でバイパスされるため、npm run dev の送信テストに影響しない。
