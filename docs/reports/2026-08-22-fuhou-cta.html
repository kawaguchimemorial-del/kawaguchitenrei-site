原因の見立て

/column/fuhou/ はサイト内でトップページに次ぐ流入を集めながら、キーイベントが0件だった。読者の多くは訃報を「受け取った側（参列者）」で、そもそも葬儀社を探していない層が相当数を占めるため、0件のすべてが導線の不備というわけではない。

ただし記事の導線側にも明確な問題があった。CTA は記事末尾に汎用のものが1つあるだけで、text を指定していなかったため ColumnBody.tsx のデフォルト文「詳しい内容や費用感は、川口典礼までお気軽にご相談ください。」がそのまま表示されていた。訃報メールの文面を調べに来た人に「費用感」と提示しても接続しない。

一方で、この記事には訃報を「出す側」＝ご喪家も確実に含まれる。とくに「訃報メールに必ず入れるべき5つの項目」で葬儀日程・葬儀形式に触れる箇所は、日程や形式が未定であれば葬儀社もまだ決まっていない可能性がある局面で、記事内で最も相談に近い接点である。ここに導線が無かった。

3. 変更内容

変更は lib/columns.ts の slug: "fuhou" の記事データのみ。コンポーネント（components/column/ColumnBody.tsx）は cta ブロックが text による文言差し替えに対応済みのため未変更。

  1. 記事中盤に文脈CTAを追加（「訃報メールに必ず入れるべき5つの項目」直後）
    { type: "cta", label: "葬儀の日程・形式を相談する", href: "/contact/", text: "訃報をお知らせする段階で、葬儀の日程や形式がまだ決まっていないこともあります。川口市周辺で葬儀社をお探しでしたら、24時間365日ご相談を承っています。" }
  2. 末尾CTAの文言を訃報の文脈に差し替え（デフォルトの費用文言をやめ、文面・連絡範囲の相談を受ける旨に）
    text: "訃報の文面やお知らせする範囲についてのご相談も承っています。はじめてのことで迷われたときは、川口典礼までお気軽にお声がけください。"
  3. 関連リンクに1本追加（既存2本＝死亡届・川口市の葬儀ガイドに加えて）
    「葬儀プラン一覧｜直葬・一日葬・家族葬の内容と費用」→ /plan/
  4. 記事冒頭のリード（quote）・本文・見出し構成・metaDescription は変更なし。

CTA は中盤・末尾の計2つに留め、/column/jiyusou/ と同じ密度にした。煽り表現・断定表現は使用していない。
