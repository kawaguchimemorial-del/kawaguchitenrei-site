2. 障害対応：SEOダッシュボードのデータ取得失敗

事象

管理画面 /admin/seo/ が「データを取得できませんでした。」と表示。Search Console データが全く出ない状態。

原因

Google OAuth の refresh_token が失効していた。

認証の最初の段階（refresh_token → access_token 交換）で次のエラー：

invalid_grant | code=400 | http=400 | desc=Token has been expired or revoked.

コード・エラーハンドリング・環境変数の設定自体に問題はなし。ダッシュボードは失敗を ok:false に握り潰す設計のため、画面には汎用メッセージのみ表示され、実エラーはサーバーログ（[search-console] fetch failed: ...）にのみ出力される。

根本要因

OAuth 同意画面が「テスト中（Testing）」公開ステータスのままだったため、Google の仕様により refresh_token が約7日で自動失効。.env.local の最終更新（2026-05-27）から約9日経過しており、時系列も一致。「動いていたのに急に止まった」典型パターン。

対応

  1. 既存スクリプト scripts/get-refresh-token.mjs でブラウザ承認 → 新しい refresh_token を再取得。
  2. 値を画面に出さず、スクリプト経由で .env.local の GOOGLE_OAUTH_REFRESH_TOKEN を更新。
  3. ローカルで実クエリ成功を確認（access token OK、データ返却）。
  4. Vercel ダッシュボードの環境変数を同じ値に更新 → 再デプロイ。
  5. 恒久対策：Google Cloud Console の OAuth 同意画面を「本番（In production）」に変更し、7日失効を解消。

再発時の切り分け手順（メモ）：同症状が再発したら、まず Vercel の Functions ログで [search-console] fetch failed: ... の実エラー本文を確認する。invalid_grant なら refresh_token 再取得、それ以外なら CLIENT_ID/SECRET・GSC プロパティ権限・サイトURL設定を確認。

核心の発見：専用プランページ（家族葬・一日葬・直葬など）が全形式そろって存在し、各ページの文言SEO（metaTitle・結論先出し・FAQ・関連リンク）もすでに十分に最適化されている。にもかかわらず、Google は多くの地名×形式クエリで専用ページではなくトップ / を当てている。

なぜトップに負けているか

  1. ページの新しさ：リニューアルでURL構造が変わり、専用プランページはまだ約2週間。Google が評価をトップから専用ページへ移し終えていない。
  2. 内部リンク評価の偏り：トップが最も内部リンク・権威を集めており、専用ページの topical signal が不足。暫定的にトップが当たっている。

＝ コンテンツ不足ではない。したがって metaTitle 等の書き換えは効果が薄く不要。打ち手は「内部リンク集約」と「再評価の促進＋時間」。

5. リダイレクト監査（旧URL→新URL）

問題なし next.config.ts の redirects() は網羅的。旧URLは301で新ページへ正しく転送されている。

  • /shimin_sou → /plan/kawaguchi-shimin/
  • /kazoku_sou → /plan/family-funeral/
  • /kawaguchi_hall → /hall/kawaguchi-memorial-hall/
  • /kasou_sikijou → /area/kawaguchi/
  • /Column_list/:slug* → /column/:slug* ／ /QA/:slug* → /column/ ほか多数

GSCに旧URLが残るのは301統合の進行中であるため。数週間で新URLへ評価が寄る見込み。対応不要。
