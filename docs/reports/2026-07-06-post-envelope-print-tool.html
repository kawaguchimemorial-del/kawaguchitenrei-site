封筒宛名印刷ツール /post 新設（社内用・検索非公開）

作成日：2026-07-06 対象：/post ・ /post/print（社内用） 担当：Claude Code

目的

長形3号（120×235mm）封筒に宛名を印刷する社内専用ツール。宛先を入力して「印刷確定」で印刷ページへ移動し印刷する。検索・Google 検索には出さない。

実装内容

  • app/post/layout.tsx（新規・server）：robots: index:false / follow:false / nocache / googleBot 無効 を付与し /post 配下を検索除外。
  • app/post/page.tsx（新規・client）：入力フォーム。
    • 郵便番号→ zipcloud API（zipcloud.acknowledge.jp・キー不要）で都道府県+市区町村+町域を自動入力（7桁で onBlur 自動＋「住所を自動入力」ボタン）。番地・建物は手入力。取得失敗時は手入力にフォールバック。
    • 住所／住所2（建物名・部屋番号・任意）／宛名／敬称（様・御中の選択）。
    • 「印刷確定」で入力を sessionStorage に保存し /post/print/ へ遷移（宛名未入力時は不可）。
  • app/post/print/page.tsx（新規・client）：長形3号レイアウトを描画。「印刷する」で window.print()。
    • 印刷CSS：@page { size: 120mm 235mm; margin: 0 }、印刷時は封筒（#envelope）以外を非表示（ヘッダー等も隠れる）。
    • 横書き配置：郵便番号（〒 000-0000）→ 住所/住所2 → 宛名+敬称（中央・大きめ）。
    • データが無い場合は入力ページへ戻る導線を表示。
  • app/robots.ts：disallow に /post/・/post を追加（noindex と二重で検索除外）。sitemap には未追加（手動管理のため元から含まれない）。
プライバシー：宛先（住所・氏名）はブラウザ内（sessionStorage）でのみ保持し、Webhook・API・サーバへ送信/ログ出力しない。外部通信は郵便番号→住所の zipcloud 参照のみ（郵便番号だけを送る）。保護ファイル（Header/Footer/MobileBottomCTA・package.json）は未変更。依存追加なし。

確認結果

  • npm run build 成功。静的生成 135→137（/post・/post/print を追加、いずれも static・noindex）。TypeScript エラーなし。
  • 実機動作（郵便番号自動入力・印刷レイアウト）は npm run dev → http://localhost:3000/post/ でご確認ください（zipcloud 参照と window.print() はブラウザ実行のため）。
  • 禁止表現・価格・個人情報の記載なし。

更新（2026-07-06）：住所自動入力の CORS 対応

公開後、郵便番号の自動入力が「住所の取得に失敗しました」となる不具合を修正。原因は zipcloud が通常の fetch（クロスオリジン）を許可しないため。app/post/page.tsx の住所取得を JSONP（script タグ・callback パラメータ）方式に変更（8秒タイムアウト・失敗時は手入力フォールバック）。送信するのは郵便番号のみ。build 137/137 維持。

更新2（2026-07-06）：住所APIの多重化（zipcloud ダウン対応）

JSONP に変えても失敗が続いたため調査。サーバ側 curl で zipcloud が空応答＝ダウンと判明。CORS 対応（Access-Control-Allow-Origin: * 確認済）の api.zipaddress.net を第1候補（通常 fetch・data.fullAddress）、zipcloud(JSONP) を予備にする二段構えへ変更。334-0001→「埼玉県川口市桜町」取得を実証。build 137/137。

更新3（2026-07-06）：印刷版面を封筒作法（縦書き）に作り直し

「封筒に印刷するレイアウトになっていない」との指摘を受け、印刷ページ（app/post/print/page.tsx）を全面改訂。

  • 版面＝封筒実寸：@page { size:120mm 235mm; margin:0 }、html,body の余白も0に。封筒面の絶対座標に印字。
  • 縦書きを既定：郵便番号=上部横並び（枠に合わせる想定）、住所=右側に縦書き（2列目の建物名は一段下げ）、宛名=中央に大きく縦書き＋敬称（様／御中）。
  • 数字を全角変換して縦書きで正立（440-1 が横倒しにならない）。
  • 縦書き／横書きトグルを操作バーに追加（横書きは社内簡易用）。
  • プリンタ側は「長形3号（手差し）」設定が前提。build 137/137。

※印字位置（郵便番号枠・住所・宛名の mm 座標）は実機で刷ってからの微調整前提。ズレ方向を教えていただければ座標を詰めます。

更新4（2026-07-06）：実機の試し刷りから郵便番号の位置を調整

実際に印刷した封筒（public/images/tmp/封筒/ の scan）を確認。郵便番号の数字が赤枠より下＋左寄りで幅が狭く、7枠に対応していなかった。

  • 縦：top 12mm → 11.2mm（上へ0.8mm）。
  • 横：単一の letter-spacing をやめ、各桁を 7mm 幅のセルに入れて枠ピッチに合わせ、3桁目と4桁目の間に 3mm の区切りを追加。right 17mm → 6mm で全体を右へ寄せ、枠の右端に合わせた。
  • 住所・宛名は指摘なしのため変更なし。build 137/137。

※プリンタの版面オフセット（@page とハード余白の差）があるため、mm は相対調整で詰める運用。次の試し刷りのズレ量を教えていただければさらに合わせます。

更新5（2026-07-06）：下60mm（ロゴ帯）回避＋郵便番号枠は6人パネルで検討中

  • 下60mm のロゴ帯を回避：宛名・住所・建物名を封筒上175mm以内に制約。住所 maxHeight 145mm＋overflow hidden（30+145=175）、宛名は 55〜175mm の領域に上下中央寄せ（height:120mm; align-items:center; maxHeight:120mm; overflow:hidden）。画面には「ロゴ帯（印刷しません）」の目安を表示（印刷はされない）。
  • 郵便番号の横位置：実機スキャン分析で枠中心≈左端65〜113mm・ピッチ約7.6mm・中央+2.5mm、かつプリンタが不定オフセット（水平+4〜6mm・垂直+27mm）を持つと判明。mm 決め打ちでは枠に確実に入らないため、6人専門家パネル（相互反論つき）で堅牢な実装（キャリブレーション等）を検討中。結果を反映予定。

更新6（2026-07-06）：郵便番号を「キャリブレーション方式」で実装（6人パネル結論）

6専門家パネル（各自が他5名を反論→統合）の結論＝ハードコードmmを廃し「規格ジオメトリ＋機体並進オフセットの2層分離＋localStorage永続化」。プリンタの不定オフセット（観測: 水平+4〜6mm・垂直+27mm）はCSS mmと1:1で対応しないため、正しい絶対mmは原理的に確定不能。機体ごとに一度合わせて保存する方式が唯一再現性が出る。

  • 各桁を左端原点で絶対配置：cx = firstCenter + i*pitch + (i>=3 ? midGap : 0)（1桁目65.0…7桁目113.1mm＝実測の枠中心65〜113mmに一致）。right基準flex/letter-spacingを廃し、左圧縮・右3枠空きを構造的に排除。3+4の区切りは i>=3（オフバイワン修正）。
  • 機体ズレは単一ラッパの translate(offsetX,offsetY) 1点で補正。規格量(firstCenter)と機体量(offset)を分離し「既定に戻す」で幾何を巻き添えにしない。
  • 永続化：localStorage: post-print-postal-calib-cho3-v1。SSRガード＋try/catch＋sanitize(clamp/NaN弾き)。既定 {firstCenter:65, pitch:7.6, midGap:2.5, boxTop:11.2, fontSize:15, offset:0}。
  • 操作UI（no-print）：折りたたみ「郵便番号の位置合わせ」に大きな矢印（左右/上下 ±0.5mm）＋現在値＋「位置を既定に戻す」。詳細設定（初回のみ）にピッチ/中央間隔/1枠目中心/枠上端/文字サイズ＋設定JSONのコピー/貼り付け。赤字で「倍率100%・用紙に合わせるOFF・ズーム100%／無地紙で試し刷りして透かし合わせ」を常時表示。
  • 画面プレビュー：各桁セルに薄赤破線の当たりを表示（印刷はされない）。「ガイド枠を印字」チェックは枠が無い封筒用（既定OFF）。
  • 住所・宛名の縦書きは一切変更なし。build 137/137。却下案＝ハードコードmm継続／赤枠の自前二重印字／中央間隔 i>=4（オフバイワン）／firstCenterに+ピッチ半分（二重補正）。

運用：初回のみ無地紙に1枚テスト印刷→封筒に重ねて矢印で枠に合わせて保存→以後は自動で同じ位置。機体・封筒を替えたら再調整。
