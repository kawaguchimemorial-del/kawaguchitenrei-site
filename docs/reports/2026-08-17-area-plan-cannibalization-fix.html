エリア・プランページの重複とカニバリ解消
10人専門家会議 ＋ サイト改修の実施記録

実施：2026-08-17 ／ 対象：kawaguchitenrei.com（本サイト）
根拠データ：同日のSEOチェック（2026-08-17-seo-check.html）／GSC確定最新日 2026-08-14
本レポートはサイト変更を伴います（lib/areas.ts・lib/plans.ts）

前提の訂正

8/3・8/9・8/17と3回連続で「様子を見る」と判断してきたが、その間に「川口市 家族葬」は19.3位→25.3位まで悪化した。

待つこと自体が判断ミスだった。7/30を最後にコードを触っていない状態が3週間続いており、「変えないから悪くなっていない」のではなく「変えない間に悪くなっている」。本日、原因が特定でき勝ちパターンが実証済みの箇所から着手する。

1. 10人の専門家による診断

A：検索意図設計

同じサイトの中に、勝ちパターンと負けパターンが並んでいる。これが最大のヒント。

ページmetaTitle28日の順位変化
/plan/direct-funeral/「川口市の直葬 | 川口市めぐりの森での火葬まで」川口 直葬 11.1→7.8位
川口市 直葬 10.3→9.0位
/plan/family-funeral/「家族葬の費用と人数の目安 | 川口市の家族葬プラン」川口市 家族葬 19.3→25.3位

直葬は「地域＋葬儀形式」をタイトル先頭に置いて改善。家族葬は同じ語が2番目にあり、しかも先頭が「家族葬の費用と人数の目安」という全国区の語。川口市のクエリで負けるのは当然。

B：カニバリゼーション分析

7/27に新設した /plan/yugure-kazokuso/ が metaTitle に「一日葬」を持ち、本文量も 11,153字 vs 5,549字と本家の2倍。 Googleが「一日葬」の代表ページを迷った結果、本家 /plan/oneday-funeral/ が 20.43位→25.79位に降格した。

夕暮れ家族葬が一日葬の一種であることは事実なので内容は正しい。問題はタイトルでの競合。

C：重複コンテンツ

lib/areas.ts の15エリアを機械比較したところ、11本が「選ばれる理由」6項目・FAQ冒頭3問とも、地名を差し替えただけの同一文だった。

西川口：「西川口からの病院・施設搬送に24時間365日対応」
東川口：「東川口からの病院・施設搬送に24時間365日対応」
川口元郷：「川口元郷からの病院・施設搬送に24時間365日対応」
南鳩ヶ谷：「南鳩ヶ谷からの病院・施設搬送に24時間365日対応」
神根・新郷・芝・安行・上青木・青木・戸塚安行 … 以下同文

これは検索エンジンが最も嫌う「地名だけ入れ替えた量産ページ」の典型。25〜78位という順位は、ペナルティではなく正常な評価。

D：内部リンク構造

エリアページへのリンク元がほぼ /saijo/ 系に限られる。その /saijo/ 自体が45.2位・307表示・0クリック。 弱いページから弱いリンクしか流れていない。エリアページ同士の相互リンクもない。

E：情報設計

西川口ページに「西川口固有の情報」が駅名以外ゼロ。 「西川口エリアからはお車でご来館いただけます」は、どのエリアにも当てはまる文で差別化にならない。

F：ローカルSEO実態

実体は西新井宿の1ホール。離れたエリアで「地域密着」を主張しても実体が薄く、順位が付かないのは当然。 ただし8/7分析のとおり、花ぜんに川口駅前の立地で勝てない以上「自社近接エリアで戦う」方針自体は正しい。方針が正しくても、今の作り方では順位が付かないという問題。

G：事実検証

距離・所要時間の捏造は禁止。「西川口から車で12分」のような数字を作ってはいけない。 差別化は「そのエリアの人が実際に困ること」で行うべきで、これなら事実を作らずに書ける。

H：地域実態 ─ 鳩ヶ谷の発見

旧鳩ヶ谷市は2011年に川口市へ編入されている。つまり鳩ヶ谷地区の住民にとって 「うちは川口市民葬を使えるのか」は本当に分からない、固有かつ高関心の疑問。

これは捏造なしに書ける本物の差別化情報であり、しかも市民葬プラン（231,000円）という商品に直結する。 現在のページには「旧鳩ヶ谷市エリアでも対応してもらえますか？→はい対応します」という中身のないFAQしかない。

I：リスク管理

15本を一度に書き換えて悪化したら、原因が特定できない。 代表2本で試し、次回チェックで効果を測ってから残りに展開すべき。削除・noindexは今回行わない（戻せない操作を最初に選ばない）。

J：事業視点

「川口市 家族葬」303表示・0クリックが最大の逸失。家族葬は主力商品（会員528,000円）で、業界平均でも家族葬は96.39万円と単価が最も上昇している領域。 エリアページ15本の議論より先に、ここを直すべき。

会議の結論

  1. 最優先は「川口市 家族葬」の受け皿修正。同一サイト内に勝ちパターン（直葬）があるため、確実性が高い
  2. 次に一日葬のカニバリ解消。原因が新設ページと特定できている
  3. エリアページは削除せず、代表2本を差別化して測定。効果が出たら残りに展開
  4. 距離・時間などの新しい事実は作らない。差別化は「そのエリアの人が実際に困ること」で行う

5. GBP API の承認状況について

現時点では確認できませんでした（理由と対処を記載します）

scripts/gbp/dump.mjs を実行した結果：

API エラー (status 403): Request had insufficient authentication scopes.

これは「APIが未承認」というエラーではありません。 手元の .env.local にある認証トークンがSearch Console用のスコープしか持っておらず、GBP用のスコープ（business.manage）が含まれていないため、 そもそもAPIに問い合わせられていない状態です。承認されているかどうかの判定ができません。

確認方法① いちばん確実 ── 再認証すれば私が判定できます

次のコマンドをターミナルで実行してください。Claude Codeのプロンプトで ! を先頭に付けると、この会話の中で実行できます。

node --env-file=.env.local scripts/get-refresh-token.mjs --scope=all
  1. ブラウザが開くので kawaguchi.memorial@gmail.com でログイン
  2. 「ビジネスプロフィールの管理」の権限を許可
  3. ターミナルに新しいリフレッシュトークンが表示されます
  4. それを .env.local の GOOGLE_OAUTH_REFRESH_TOKEN に上書き保存

そのあと私が node scripts/gbp/dump.mjs を実行すれば、承認済みかどうかを確定的に判定できます。

判定の読み方（再認証後に私が確認します）
・アカウント情報が返ってくる → 承認済み
・PERMISSION_DENIED ／ The caller does not have permission → まだ承認されていない
・SERVICE_DISABLED → Cloud Console側でAPIが有効化されていない

確認方法② Gmailを検索する（松澤様のお手元で今すぐできます）

kawaguchi.memorial@gmail.com で、次のキーワードで検索してみてください。

検索キーワード探しているもの
Business Profile API承認・却下の通知メール本体
from:google.com Business ProfileGoogle からの関連通知すべて
"Google Business Profile APIs"申請受付・審査結果の定型メール
quota または Standard Accessアクセス枠の付与通知
迷惑メール・プロモーションタブも確認この種の通知は振り分けられやすいです

申請は2026-07-30に提出済み（docs/operations/gbp/2026-07-30-gbp-api-access-request.md）。審査は通常2〜6週間程度かかるため、まだ結果が出ていない可能性もあります。

確認方法③ Google Cloud Console で見る（メールが見つからない場合）

  1. console.cloud.google.com に kawaguchi.memorial@gmail.com でログイン
  2. 該当プロジェクトを選択
  3. 左メニュー →「APIとサービス」→「有効なAPIとサービス」
  4. 「Google My Business API」または「Business Profile API」を開く
  5. 「割り当て（Quotas）」タブを見る

読み方：
・Requests per minute が 0 → 未承認（申請中）
・Requests per minute が 300 など0より大きい → 承認済み
※ 2026-08-09時点では 0/300 QPM で未承認でした。ここが変わっていれば承認されています。

この画面のスクリーンショットをいただければ、私が判定します。数値だけ教えていただく形でも構いません。
