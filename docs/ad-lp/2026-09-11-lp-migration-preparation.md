## 0. 最優先：切替前に必ず潰す問題が1つある

**`lp_*` イベントが、期待どおりに GA4 へ記録されていない。**

2026-08-15〜09-10 の実測（`node --env-file=.env.local scripts/ad-lp-report.mjs --start 2026-08-15 --end 2026-09-10`）：

| 区分 | セッション | 記録されたイベント |
|---|---:|---|
| **LP入口** | **27**（Organic 14／Direct 13） | **`generate_lead` 8 ／ `lp_view` 4** |
| 本サイト入口 | 746 | `click_tel` 25 ／ `generate_lead` 13 |
| 内部入口 | 13 | なし |
| 入口不明 | 38 | なし |

**問題点**

1. **`lp_generate_lead` が 0 件。**同じフォーム成功に対して `generate_lead` は 8 件記録されている。
   **同じページ・同じセッション・同じ除外判定を通っていながら、片方だけが届いていない。**
2. `lp_click_tel` `lp_contact_open` `lp_plan_open` `lp_form_start` `lp_directions` も **すべて 0 件**。
3. `lp_view` は 27 セッションに対して **4 件**しかない（LP配下の画面表示ごとに発火する実装）。

**技術的な差分（原因の候補）**

| 送出方法 | 実装 | 結果 |
|---|---|---|
| `pushGenerateLead`（`lib/analytics.ts`） | `dataLayer.push({ event: "generate_lead", ... })` ＝ **dataLayer イベントオブジェクト** | ✅ 届いている（8件） |
| `trackLpEvent`（`lib/lp-analytics.ts`） | `dataLayer.push(arguments)` ＝ **gtag コマンドキュー形式**（`("event", name, params)`） | ❌ ほぼ届いていない |

除外ガード（`window.kawaguchiAnalyticsAllowed()`）は両方が同じものを通っているため、**除外設定が原因ではない。**
違いは**送出の形式**だけ。手順書にも「GTMのdataLayerイベントオブジェクトだけを探すテストでは確認できないため、
Googleタグの送信とGA4受信を確認する」と注意書きがある箇所で、**実際に受信できていない可能性が高い。**

`lp_view` が4件だけ届いていることから、「まったく動かない」のではなく
**Googleタグ（gtag.js）の読み込み前に送出してしまい取りこぼしている**、という可能性も考えられる
（`lp_view` は画面表示直後に発火、`generate_lead` はフォーム送信後＝タグ読み込み完了後に発火）。

> ⚠ **原因を断定しない。** 実機で送信と受信を確認したうえで直す。
> いま広告を `/lp/` に向けると、**切り替えた瞬間から電話タップもフォーム開始も測れない状態**になる。

### やること（順序）

1. 本番 `/lp/?analytics=on` を開き、ブラウザの開発者ツールで
   - `dataLayer` への push が起きているか
   - GA4 の **DebugView / リアルタイム**に `lp_view` `lp_click_tel` が届くか
   を確認する（手順書「テスト・内部利用の除外」に従い、終了後は `?analytics=off` に戻す）
2. 届いていなければ、送出方法を `generate_lead` と同じ **dataLayer イベントオブジェクト形式**へ揃える
   - `CLAUDE.md` §21：**LPイベントは既存タグへ直接送出し、GTMで同名タグを重複実装しない**。
     この原則は維持したまま、**届く形式に直す**のが趣旨に合う
3. 直したら 1 を再実行して受信を確認する
4. **これが終わるまで広告の切替日を確定しない**

### 2-6. 意図に関係なくやる価値がある2つ

**① ドメインプロパティ `sc-domain:kawaguchitenrei.com` を追加する**

現在の `https://kawaguchitenrei.com/` は**URLプレフィックス**のプロパティで、`www` 付きのURLを含まない。

実測（2026-09-11）：

```
https://www.kawaguchitenrei.com/   → 200（リダイレクトせずそのまま表示される）
http://kawaguchitenrei.com/        → 308 → https://kawaguchitenrei.com/
```

`www` 側は canonical が `https://kawaguchitenrei.com/` を指しているため検索上の実害は小さいが、
**`www` で発生した表示・クリックは現在のプロパティでは見えない。**
ドメインプロパティを追加すれば `www`／非`www`／`http`／`https` を1つでまとめて見られる。
DNS での所有権確認が必要（既存プロパティはそのまま残してよい）。

**② 広告LPドメイン `kawaguchi-memorial-hall.com` を Search Console に登録する**

移行後にこのドメインを検索から下げるには、**Search Console の所有権が必要**になる。

- 2026-09-11 のSEOチェックで、このドメインが**実際に検索結果に出ていることを確認済み**
  （`docs/reports/2026-09-11-seo-check.html` §3.5）
- 当社の「川口メモリアルホール」の表示回数が 350 → 155 と半減した原因と整合する

- ⚠ ただし **`noindex` を入れるにはサイト自体の編集が必要**。

- **取得できない項目は「未取得」と書く。タップで代用しない**
- **広告費÷タップ単価**と**広告費÷有効相談単価**は別の指標
- 旧LPと比較するときは、期間・配信面・検索語句・料金表現・CV定義・計測可能性の違いを明記する
- **同時に広告設定も変わるので、「LP改修だけの効果」とはしない**
