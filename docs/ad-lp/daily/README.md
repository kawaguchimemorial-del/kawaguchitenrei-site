# 広告LP（/lp/）日次チェック

2026-09-25 松澤依頼：**LPの状態を毎日チェックし、記録を積み上げる。**

## 手順
1. `node --env-file=.env.local scripts/lp-daily-check.mjs YYYY-MM-DD > tmp/lp-daily/YYYY-MM-DD.json`（読み取り専用・集計値のみ）
2. `lp-daily-log.md` の表に1行追加し、気づきを日付見出しで追記
3. 実着信の件数（松澤から）がわかれば「実着信」列に入れる

## 読み方の注意
- **GA4 は直近およそ48時間のデータが未確定。** チャネル（Paid Search／Cross-network）とセッションの帰属が後から変わる。
  2026-09-22 の「P-MAXへの入れ替わり」「セッション分割」は未確定データの見かけで、9/25 時点の再取得で解消していた（Paid Search 300・分割1件）。
  → **判断は2日以上前の日で行う。** 前日分は「速報」と明記し、翌々日に確定値で上書きする
- 電話タップは「押された回数・人数」で、着信数ではない。9/23 15:45 頃から誤発信対策（10秒以内の再タップ・長押し・複数タッチを無効）が入っている
- `cta_placement`・`plan_slug` は 2026-09-23 登録。それ以前は取れない
- **区画ごとの到達（`lp_section_view`）は 2026-09-25 導入。** 区画が画面の縦中央の線にかかったときに、ページ表示ごとに1回。区画名は `cta_placement` に入る（hero → phone_box → urgent → reasons → price → halls → preneed → voice → hall_map → flow → faq → contact）。前の区画との人数差が、その区画での離脱
- テスト送信（当社・代理店）は lead 件数に混ざる。わかる範囲で注記する
