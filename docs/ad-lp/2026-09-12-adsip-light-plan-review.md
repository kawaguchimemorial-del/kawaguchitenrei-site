# AdSiP 0120ライトプランで新LPの電話計測は足りるか（2026-09-12）

- 資料：`public/images/tmp/リスティング/報告/コールトラッキング/`
  - `AdSiPプラン一覧 -20230721.pdf`
  - `AdSiPご提案書v3.5.pdf`（全30頁）
  - `AdSiPキーワード・メディア計測プランご提案書_v2.4.pdf`
- 論点：代理店より「**ライトプランでも一定通話時間をフィルタにして計測できる**」との説明。
  これで新LP（`kawaguchitenrei.com/lp/`）の要件を満たすか
- 関連：`docs/operations/2026-09-10-call-tracking-proposal.html`、`2026-09-11-nextup-gtm-container-review.md`

---

## 結論

**ライトプランで問題ない。** ただし「**できること**」と「**できないこと**」を分けて理解したうえで導入する。

| 目的 | ライトプランで足りるか |
|---|---|
| **A. 広告からの電話が実際に何件鳴ったかを、当社が独立して知る** | ✅ **足りる** |
| **B. 実着信を Google 広告のコンバージョンにして、入札を最適化する** | ❌ **できない**（外部ツール連携が「不可」） |
| C. キャンペーン別（指名／一般KW／DG／P-MAX）に電話を分ける | ❌ できない（番号の出し分けにタグ設置が必要） |

**当社がいま解きたいのは A。** 8月の媒体CV57件が実体を伴うか分からない、という問題を解くのが先。
B と C は、実着信の水準が分かってから検討すればよい。**いまライトプランで始めて差し支えない。**

## 1. 「通話時間フィルタ」は確かにできる

代理店の説明どおり。根拠は提案書の次の頁。

| 頁 | 記載 |
|---|---|
| p10「通話ログ例」 | 「いつ、どの媒体をみて、**どのくらい**、電話が発生したのかをリアルタイムで確認可能」。ログの項目に**通話時間**・発信者情報・通話ステータス・広告媒体 |
| p11 | 「通話ログは**ダウンロード可能**！簡単に**グラフ化する機能も無料**でご提供」 |

→ **「60秒以上の着信だけを数える」は確実にできる。**

### これが当社にとって重要な理由

`GTM-N2J5GBXL` のコンバージョン①は「`tel:` リンクのタップ」で、**実際に通話になったかは分からない**。

通話時間で分ければ、次のように分解できる。

| 通話時間 | 想定される中身 |
|---|---|
| 〜10秒 | 誤タップ、かけ間違い、すぐ切れた |
| 10〜60秒 | 参列者の問い合わせ（式場の場所・日程）、営業電話 |
| 60秒〜 | **ご相談の可能性が高い** |

**タップ数と実着信数と「60秒以上」の3つが並ぶと、広告の評価がまったく変わる。**

> ⚠ 提案書 p17 の「条件付きアフィリエイト設定（通話秒数60秒）」は、
> **ペイパーコール広告で媒体運営者へ成果報酬を払うための機能**であって、当社の用途とは別。
> 当社が使うのは p10・p11 の**通話ログと通話時間**のほう。混同しない。

## 2. ⚠ 最大の限界：外部ツール連携が「不可」

プラン一覧（`AdSiPプラン一覧 -20230721.pdf`）に明記されている。

| プラン | 計測方法 | 外部ツール連携 | 料金単位 |
|---|---|---|---|
| **0120ライトプラン** | 計測用番号を**メディアに表記するのみ** | **不可** | 計測用番号単位 |
| キーワード計測プラン | **計測用タグの設置** | **Google広告／Yahoo!広告／Google Analytics／Salesforce** | セッション単位（目安 1,500セッション5番号） |
| メディア計測プラン | 計測用タグの設置 | 不可 | 計測用番号単位（最低2番号） |

**つまりライトプランでは、実着信を Google 広告へコンバージョンとして戻せない。**

### これをどう受け止めるか

**当面は問題にならない。**理由は3つ。

1. **広告のコンバージョンは `GTM-N2J5GBXL` 側で既に取れている**（`tel:` タップ＋フォーム送信完了）。
   入札の最適化はそちらで動く
2. **実着信は「広告を評価するための当社の物差し」として使う。**
   入札に組み込まなくても、月次で「タップ◯件に対して実着信◯件、うち60秒以上◯件」が出れば、
   広告費の判断には十分
3. **代理店の数字を検算できるようになることが目的。**
   これは連携しないほうがむしろ独立性が保てる

> 逆に言えば、**「実着信で入札を最適化したい」となった時点でライトプランでは足りない。**
> その場合はキーワード計測プラン（別提案書・セッション単位課金）へ切り替える。
> ただしそれは**実着信の水準が分かってから**の判断。

## 3. ⚠ 番号は1本。キャンペーン別には分けられない

ライトプランの計測方法は「**計測用番号をメディアに表記するのみ**」＝**静的な番号割り当て**。

- `/lp/` に固定で1番号を出す → 「広告全体から何件」までしか分からない
- 指名／一般KW／DG／P-MAX の別は分からない
- 最大5番号まで使えるが、**1つのページで訪問者ごとに番号を出し分けるにはタグ設置が必要**
  （＝キーワード計測プラン）

**`/lp/` が単一の着地先である以上、1本で始めて問題ない。**
キャンペーン別の電話が知りたくなったら、そのときに方式を見直す。

---

## 4. ⚠ Google広告の「通話レポート」と同じページで併用しない

`docs/operations/2026-09-10-call-tracking-proposal.html` で案A（Google広告の専用転送電話番号・無料）と
案B（当社名義の番号）を比較した。**この2つは同じページでは併用できない。**
Google の転送番号はページ上の番号を**書き換える**ため、AdSiP の番号が消えてしまう。

**整理（前回の結論を維持）**

| ページ | 使う番号 |
|---|---|
| **`/lp/`**（広告の着地先） | **AdSiP の計測番号**（当社名義・当社が数える） |
| 本サイト | Google広告の専用転送電話番号（無料・広告経由の訪問者にだけ表示） |

## 6. ⚠ 葬儀社として入れてはいけない機能がある

提案書には便利な機能が載っているが、**当社の事業では使わないほうがよいものがある。**

| 機能 | 提案書 | 当社の判断 |
|---|---|---|
| **音声ガイダンス**（p14）<br>「LPからの入電です」と受話前に流す | 「電話を受ける前にどの媒体からの問い合わせか分かる」 | **入れない。**ご逝去直後の方を数秒でも待たせる。受け手の利便より、かけてきた方の体験を優先する |
| メール通知（p15）<br>話中・不在・時間外の着信を通知 | 「取りこぼし無し」 | **入れてよい。**取りこぼしの把握に有効。ただし**通知メールに発信者番号が載る**ため、取り扱いは個人情報として扱う（§12） |
| 営業時間外ガイダンス（p15） | 時間帯で応答を変える | **設定しない。**24時間365日受付のため、常時そのまま転送する |
| 話中待機（p18） | 混雑時に待たせる | 要検討。**待たせるより取りこぼしを記録して折り返す**ほうが当社の体制に合う |

## 7. 実装コスト：ほぼゼロ

`/lp/` の電話番号は既に1か所にまとまっている。

```ts
// app/lp/lp-constants.ts
export const PHONE_DISPLAY = "0120-963-765";
export const PHONE_HREF = "tel:0120-963-765";
```

**この2行を計測番号に書き換えるだけで、`/lp/` 配下の全箇所（トップバー・電話ボックス・CTAバンド・
固定CTA・式場案内・事前相談・フォーム・送信完了画面）が切り替わる。**

あわせて直す箇所が1つある。

```ts
// app/lp/contact/actions.ts  … 送信完了メッセージとエラーメッセージ内に番号が直書き
"…お急ぎの場合は 0120-963-765 までお電話ください。"
```

> 番号を変えても `GTM-N2J5GBXL` のコンバージョン①（`tel:` リンクのタップ）は**動き続ける**。
> 発火条件が「クリックされたリンクのURLに `tel:` を含む」であり、番号そのものを見ていないため。

## 8. 契約前に確認すること（AdSiP へ）

1. **転送先までの通話料は別途かかるか。** 料金表の「着信課金」は発信者からの着信分と読めるが、
   計測番号 → 当社代表番号への転送区間が別途課金されるのかを確認する
2. **転送の信頼性**：深夜・同時着信・話し中のときの挙動
3. **発信者番号が保持されるか**（折り返しができないと意味がない）
4. **転送の遅延と音声品質**
5. **解約条件**（1ヶ月からとあるが、解約通知の期限を確認）
6. 解約後、その番号が第三者に再利用される可能性と、そのときの告知

## 10. 実施の順序

1. AdSiP へ §8 の確認 → 見積り取得
2. 契約・番号取得（5営業日）
3. `app/lp/lp-constants.ts` と `app/lp/contact/actions.ts` の番号を差し替え（当社・数分）
4. 転送設定と着信テスト（**実際にかけて、鳴ること・折り返せることを確認**）
5. 広告の切替と同時に運用開始
6. 初月の突き合わせ：**タップ数（GTM）／実着信（AdSiP）／60秒以上（AdSiP）／手書きの着信記録**

> **3 は広告の切替より前に済ませておく。** 切替後に番号を変えると、その期間の計測が分断される。
