## 3. ⭐ 何をコンバージョンとしているかが判明した

トリガー条件を読み解いた結果：

| コンバージョン | 発火条件 | 意味 |
|---|---|---|
| **①** | `gtm.linkClick` かつ クリックされたリンクのURLに **`tel:` を含む** | **電話リンクのタップ** |
| **②** | `gtm.elementVisibility`（**特定の要素が画面に表示された**） | サンクス表示＝**フォーム送信の完了**と推定 |
| リマーケティング | `gtm.js`（**全ページの読み込み時**） | 訪問者をリマーケティングリストへ |

### ここから分かること

**8月の媒体CV57件は、「電話リンクのタップ」と「要素の表示」で計上されている。**
`CLAUDE.md` の整理どおり、**電話タップは実際の着信ではない。**
コールトラッキング（通話レポート／計測用番号）を入れたい理由が、ここでも裏づけられた。

## 4. そのまま設置した場合に起きること

| # | 事象 | 影響 |
|---|---|---|
| A | **コンバージョン①（電話タップ）は動く** | 当社の `/lp/` も `tel:` リンクを使っているため、条件を満たす |
| B | **コンバージョン②（要素の表示）は動かない可能性が高い** | 旧LPのサンクス要素（CSSセレクタ）に紐づいている。当社の `/lp/contact/` は別のDOM。**フォーム送信のコンバージョンが計上されなくなる** |
| C | **リマーケティングタグが全ページで発火する** | `gtm.js`（全ページ読み込み）がトリガー。サイト全体に入れると**本サイトの全訪問者がリマーケティングリストに入る** |

**とくに B が重要。**「そのまま貼る」と、**電話タップだけが計上され、フォーム送信は計上されない**状態になりうる。

## 6. 選択肢と当社の推奨

| 案 | 内容 | 評価 |
|---|---|---|
| **① NEXT UP の GTM を `/lp/` 配下だけに設置** | 先方の依頼どおり。ただしサイト全体ではなく `/lp/` 限定にする | **現実的。** 広告のコンバージョンとリマーケティングが継続でき、先方が自分で設定変更できる |
| ② 当社GA4のキーイベントを広告へインポート | GTM追加なし。`generate_lead` を主要CVに | 当社が中身を検証できるが、リマーケティングは別途必要 |
| ③ ①と②を併用 | — | **やらない。**フォーム送信が二重に計上される |

**推奨は①。ただし次の4条件を付ける。**

### 条件1：`/lp/` 配下だけに読み込む（全サイトに入れない）

NEXT UP の設置手順は「`<head>` の上のほうに貼る」という、**1枚もののHTMLを前提とした案内**。
当社サイトは Next.js で全ページが共通レイアウトを使うため、そのまま貼ると**本サイト全体**に入る。

→ `app/lp/layout.tsx` 側にだけ読み込む形で実装する（当社作業）。
これによりリマーケティングの対象も `/lp/` の訪問者に限定される。

### 条件2：コンバージョン②のトリガーを作り直してもらう

- 要素セレクタを **`#lp-contact-complete`** に変更（§5）
- 旧LPのセレクタのままでは発火しない

### 条件3：電話タップを「実着信」と呼ばない

コンバージョン①はタップであって通話ではない。
**通話レポート（Google広告専用転送電話番号・無料）の有効化**を併せて依頼する
（`docs/operations/2026-09-10-call-tracking-proposal.html` 案A）。

### 条件4：当社GA4からのインポートは行わない

①を採る以上、`generate_lead` を広告へインポートすると**同じ送信が2回数えられる**。
当社GA4は**観測用**として使い、広告の入札は NEXT UP のコンバージョンで最適化する。

> なお当社側の `lp_*` イベント（`2026-09-11-lp-event-fix.md`）は **GA4 での観測用**であり、
> 広告のコンバージョンとは別物。こちらは当社コンテナ `GTM-TJWKD4WB` に転送タグを1つ追加すれば動く。
> **2つのコンテナは役割が違う**（当社＝観測／NEXT UP＝広告の最適化）ので、共存して差し支えない。

### 転送量について（要判断）

`CLAUDE.md` §21.2 は `/lp/` の転送量を **brotli 50KB以下**と定めている。
現在 21.7KB。GTM コンテナ本体は brotli 146KB。

- `scripts/test-lp-output.mjs` は**HTMLの転送量のみ**を測っており、外部スクリプトは含まない
- ただし「表示速度を守る」という規定の趣旨からすると、外部スクリプトも実際の体感に影響する
- GTM は非同期読み込みのため、初回表示（LCP）は阻害しにくい

**この規定をどう適用するかは松澤の判断。**判断を記録に残す。

### 設計上の判断

| 判断 | 理由 |
|---|---|
| `/lp/` 配下だけに読み込む | リマーケティングタグが全ページ読み込み時に発火するため。サイト全体に入れると本サイトの全訪問者がリストに入る |
| 既存コンテナ（`GTM-TJWKD4WB`）には触らない | 役割が違う（当社＝GA4での観測／代理店＝広告の最適化）。2つのコンテナが `dataLayer` を共有する構成は Google が公式に認めている |
| 除外フラグを尊重する | 既存コンテナと同じ `window.kawaguchiAnalyticsAllowed()` で判定。**除外中はコンテナ自体を読み込まない**（`?analytics=off` が効く） |
| `strategy="afterInteractive"` | 非同期。初回表示を阻害しない（§21.2 の条件） |
| **`noscript` の iframe は入れない** | JavaScript が無効だと除外フラグを判定できず、`?analytics=off` を無視して計測してしまう。このコンテナのタグはすべて JavaScript 前提のため、入れても得られるものがない |
| コンテナ ID をコードに直書き | ページのソースに出る公開値。`GA4_MEASUREMENT_ID` と同じ扱い。Vercel の環境変数を増やさずに済む |
