# 04. Privacy Review（個人情報・フォーム・Webhook）

このファイルは、川口典礼サイトで扱う個人情報と、問い合わせフォーム・
外部 Webhook 連携・環境変数まわりの確認ルールを定める。

**フォーム・Webhook・環境変数を触る作業をする前に、必ず本ファイルのチェックリストを実行する**。

---

## 1. このサイトで扱う可能性がある個人情報

| 種別 | 例 |
|---|---|
| 氏名 | 喪主、相談者、故人 |
| フリガナ | 氏名のカナ |
| 電話番号 | 連絡先 |
| メールアドレス | 連絡先 |
| 住所 | お住まい、ご安置場所、葬儀場所 |
| 相談内容 | フォーム入力本文 |
| 故人情報 | 死亡日時、年齢、続柄、宗教宗派 |
| 葬儀日程 | 通夜・告別式・火葬の日時 |
| 宗教・宗派 | 仏式・神式・キリスト教・無宗教等 |
| アクセス解析情報 | IP、UA、Cookie、GA4 / GTM 識別子 |
| 画像由来情報 | 遺影・名札・会葬礼状に映る氏名 |

**これらは「個人を特定しうる情報」または「センシティブ情報」**。
扱うときは本ファイルのルールに従う。

---

## 2. 問い合わせフォーム改修時のチェックリスト

新規にフォームを追加する／既存フォームを改修する前に、以下を満たすか確認する。

- [ ] 必須項目の最小化（取らなくていい情報は取らない）
- [ ] 任意項目は「任意」と明記
- [ ] プライバシーポリシーへの同意チェックがある（必須）
- [ ] エラー表示で入力値を再表示しても XSS にならない
- [ ] サーバー側で改めてバリデーションする
- [ ] 送信完了画面で個人情報をエコーバックしない（要約のみ）
- [ ] 送信完了で GA4 / GTM の `generate_lead` イベントを発火（ただし PII を載せない）
- [ ] ログに氏名・電話・メール・住所・相談本文を出さない
- [ ] エラーをユーザーに返すときも、内部詳細（スタックトレース）を出さない
- [ ] reCAPTCHA / honeypot などのスパム対策の現状確認
- [ ] レートリミットの現状確認

---

## 3. Google Apps Script Webhook 使用時の注意

問い合わせ・概算依頼は Google Apps Script（GAS）の Webhook へ送信している前提。

- **Webhook URL は秘密**。コードにハードコードしない。`.env` で管理
- **`FORM_WEBHOOK_SECRET` を必ず Header または Body で送信し、GAS 側で検証**
- フェッチは **サーバー側（Server Action / API Route）からのみ** 実行（クライアントから直叩きしない）
- フェッチ失敗時：
  - ユーザーには「送信に失敗しました。お電話でもご相談いただけます」など穏当なメッセージ
  - サーバーログには **個人情報を出さない**
  - 再送 / DLQ の設計は別途検討（現状は人間が監視）
- GAS 側の応答が遅延する場合に備えて、フェッチに `AbortSignal.timeout` を設定する

---

## 4. `FORM_WEBHOOK_SECRET` の扱い

- 値を **コード・ログ・コミットメッセージ・PR 本文に出さない**
- `.env.local` で管理（リポジトリにはコミットしない）
- 値が漏洩した場合は **即時ローテーション**（GAS 側 / Vercel 環境変数の両方）
- Claude Code は値を **読まない・表示しない・出力しない**
- ローテーション手順を運用ノート化（誰がいつローテートするか）

---

## 5. `.env` ファイル運用ルール

- `.env` / `.env.local` / `.env.development.local` / `.env.production.local` は
  **読まない・表示しない・編集しない・コミットしない**
- `.gitignore` に確実に入っていることを定期確認
- 必要な環境変数の **キー名と用途**だけは `docs/` か README にメモしてよい
  （値は絶対に書かない）
- 環境変数は Vercel ダッシュボード（Production / Preview / Development の使い分け）で管理

---

## 6. ログ・エラー報告のルール

- 個人情報（氏名・電話・メール・住所・相談内容・故人情報・葬儀日程）を
  `console.log` / 例外メッセージ / Sentry / Vercel ログ に **出さない**
- 必要な情報は ID 化・ハッシュ化（例：問い合わせ ID `inq_xxxxxx`）
- ログレベルを使い分け（`info` / `warn` / `error`）。デフォルトで PII を含まない

---

## 7. 施工事例・口コミ・画像のルール

### 7.1 文章コンテンツ

- **故人名・喪主名を出さない**
- 地域は **町名程度まで**（番地・建物名は禁止）
- 宗派・宗教は **粒度を抑える**（特定の宗派名で個人特定に近づかない）
- 年齢は **年代表現**（「80 代」程度）
- 続柄は OK（「ご長男様」など）
- 創作の声・口コミを書かない。事実ベース

### 7.2 画像コンテンツ

- **遺影・名札・会葬礼状に映る氏名・写真は掲載しない**
- 掲載前に **人間が必ず確認**
- 顔・氏名が映る画像はモザイク・トリミング処理
- 寺院会館・民営式場の写真を **無断で掲載しない**
- 他社サイト・素材サイトの画像を **無断使用しない**
- alt にも個人特定情報を入れない

---

## 8. 人間確認が必須な作業

以下は Claude Code に判断させず、必ず人間が最終確認する。

- 画像の掲載可否（遺影・名札・会葬礼状が映っていないか）
- 口コミの掲載可否（個人特定リスクがないか）
- 施工事例の掲載可否（同上）
- 競合他社名を出すコンテンツの掲載可否
- 価格表の改訂
- プライバシーポリシー・利用規約の文面変更
- フォーム動作の本番デプロイ前テスト
- Webhook シークレットのローテーション
- 環境変数の追加・変更

---

## 9. Claude Code にやらせてよい作業 / やらせない作業

### 9.1 やらせてよい

- フォーム UI / バリデーション / エラー表示の改修（Privacy Review チェック後）
- 構造化データ追加
- 文言修正（本ファイル §6 / §7 の制約を満たす範囲）
- 内部リンク追加・修正
- ページ追加（テンプレートとデータに基づく）
- 画像の `alt` 修正（個人特定情報を含まない）
- 既存画像ファイル名・配置の維持（リネーム禁止）

### 9.2 やらせない

- `.env*` の読み取り・表示・編集
- `FORM_WEBHOOK_SECRET` の値の出力
- 個人情報を含むログ出力の追加
- 故人名・喪主名のサンプルテキスト埋め込み
- 競合他社サイトの文章コピー
- 「絶対に」「必ず」「最安保証」など断定表現の追加
- 本番デプロイ操作（最終的に人間が確認）
- スキーマや DB の破壊的変更

---

## 10. フォーム改修フローの推奨手順

1. 改修内容を `docs/03-improvement-roadmap.md` で位置付け
2. 本ファイル §2 のチェックリストを通す
3. ローカルで実装（個人情報を含まないテストデータで動作確認）
4. `npm run build` / `git status` で差分確認
5. 人間が PR レビュー
6. プレビュー環境でフォーム送信テスト（テストデータ）
7. 本番デプロイ
8. 本番で送信テスト（数件）→ Webhook 着信を確認
9. 必要に応じて GTM / GA4 のイベントを確認
