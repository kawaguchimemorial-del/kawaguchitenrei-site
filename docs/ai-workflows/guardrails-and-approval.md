# Guardrails と Human Approval — 川口典礼サイト固有

このプロジェクトの安全設計（ガードレール）と人間承認の境界線を明文化する。
AI（Claude Code 含む）が単独で踏み越えてはいけない領域をここに集約する。

このファイルは **上位ルール**。`CLAUDE.md` / `AGENTS.md` / `docs/00〜05` と矛盾する箇所がある場合、より厳しい方を採用する。

---

## 1. 機密情報の取り扱い（絶対）

### 1.1 ファイル

- `.env` / `.env.local` / その他 `.env*`、`credentials*`、`secret*` は
  - **読まない**（Read / Bash / PowerShell 経由でも）
  - **表示しない**
  - **編集しない**
  - **コミットしない**
- これらに該当する可能性があるパスは、ツール呼び出し前に判断して避ける

### 1.2 値

- `FORM_WEBHOOK_SECRET` / Webhook URL / API キー / トークン / DB 接続文字列は
  - **コードに残さない**
  - **コミットメッセージに含めない**
  - **ログ・標準出力・標準エラーに出さない**
  - **docs に貼らない**
- 一度でも出力した可能性があれば、必ずユーザーに報告（隠蔽しない）

### 1.3 個人情報

- 氏名・電話番号・メールアドレス・住所・相談内容・故人情報・葬儀日程は
  - **ログ出力しない**
  - **コードコメントに残さない**
  - **docs に残さない**
- フォーム送信データ・問い合わせデータをローカルに保存しない

## 2. フォーム / Webhook / GAS — Privacy Review 必須

以下の領域に変更が及ぶときは **必ず Privacy Review を実行**（`docs/04-privacy-review.md` のチェックリスト）：

- `components/**/contact*`、`components/**/form*`
- `app/contact/`、`app/api/**`
- `app/estimate/`
- Google Apps Script 連携コード
- バリデーション、エラー表示、Webhook 送信、確認画面

**触らないと壊れる箇所**（明示指示なく変更しない）:
- 既存のバリデーションロジック
- Webhook の送信先・送信形式
- エラーメッセージの仕様

## 3. 公開コンテンツの人間承認境界

以下は **AI が単独で公開判断しない**。必ず人間が公開前に確認する：

- 施工事例（`/case/`）
- 口コミ（`/voice/`）
- 遺影・名札・会葬礼状・参列者が写る画像
- 喪主・故人・施主の名前が出る可能性のあるコンテンツ
- 顧客の特定につながる日時・地名・施設名の組み合わせ

---

## 4. 価格表記ルール（厳格）

- **正本は `CLAUDE.md §9`**。それ以外の価格を勝手に書かない
- 「税込・税別」の区分が不明な金額には「税込」と勝手に書かない
- 「目安」と表記し、「正式なお見積り時に確認」を併記する場合に限り提示可
- 禁止語: **「必ず追加費用なし」「絶対に最安」「総額確定」「○○円ポッキリ」**

---

## 5. トーン・表現の禁止語（全ページ）

葬儀サイトとしての品位とご遺族への配慮を最優先する。以下は **全面禁止**：

- **断定**: 「必ず」「絶対」「100%」「確実に」「断言します」
- **最上級**: 「最安」「No.1」「業界最高」「唯一」
- **不安喚起**: 「今すぐ決めないと損」「後悔しない唯一の方法」
- **押し売り**: 「今すぐ申し込み」「限定キャンペーン中」（葬儀サイトとして不適切）
- **競合誹謗**: 競合他社の名前と組み合わせた優劣の断定
- **未確認の距離・所要時間**: 事実確認できない「車で○分」「徒歩○分」

代替案: 「目安」「ご相談ください」「無料でご案内」「事前のご検討も歓迎」など、控えめな表現に置き換える。

## 6. push と本番影響の人間承認

### 6.1 push は必ず人間承認

- `git push origin main` は **明示指示があったときだけ**実行
- 「コミットしておいて」とだけ言われた場合、push はしない
- push 前に必ず:
  1. `git status`
  2. `git log --oneline -5`
  3. `origin/main` との ahead/behind 確認
  4. working tree clean か確認
  5. push 対象のコミットハッシュをユーザーに確認

### 6.2 本番影響の大きい変更は事前提案

以下のファイルは **明示指示なく触らない**：

- `components/layout/Header.tsx`
- `components/layout/Footer.tsx`
- `components/layout/MobileBottomCTA.tsx`
- `package.json`（依存追加・スクリプト変更・バージョン変更すべて含む）
- `next.config.ts`
- `funeral-system/` 配下一式

必要だと判断した場合も、**まず提案して承認を得る**こと。

## 7. 不可逆操作・破壊的操作

以下は **明示指示があっても、念のため再確認**してから実行：

- `git push --force` / `--force-with-lease`
- `git reset --hard`
- `git checkout --` / `git restore .`（未コミット変更の破棄）
- `git clean -f` / `-fd`
- `git branch -D`
- `rm -rf` / `Remove-Item -Recurse -Force`
- ファイル・ディレクトリのリネーム・削除（特に画像・docs）
- 依存削除（`npm uninstall`）
- DB / 本番リソースの直接操作

**安全代替**: 一度コミットしてから操作、ブランチを切ってから操作、バックアップを作ってから操作。

---

## 8. Search Console の不可逆操作

以下は **必ず人間が判断**：

- URL 削除リクエスト
- noindex を本番に投入
- canonical を別 URL に切り替え
- リダイレクト（301 / 308）の新規追加
- カバレッジでの「除外」「警告」への対応で URL を変更
- インデックス登録リクエストを **短期間に何度も繰り返す**（Google ガイドライン違反）

---

## 9. 顧客対応・外部通知の禁止

AI は **顧客への通知系操作を自動で行わない**：

- 顧客へのメール送信
- 顧客への電話
- 問い合わせフォームへのテスト送信（本番フォームに対しては禁止）
- LINE・SMS など外部通知
- 自動返信メールのテンプレ変更（仕様変更扱い → Privacy Review）

---

## 10. AI 出力の表現範囲

AI が生成・提案する文言は、以下を満たすこと：

- ご遺族への配慮を最優先
- 葬儀社サイトとしての品位
- 既存トーン・既存ページの言い回しと整合
- 「読み物」として落ち着いて読める
- カードを並べる訴求より、語りかける構成

詳細は `docs/05-content-guidelines.md` を参照。

## 11. AI 作業ログの保存

以下の知見は **使い捨てにせず保存**する：

- 施策完了 → `docs/eval/records/`
- 手動運用ログ → `docs/operations/`
- 再利用プロンプト → `docs/prompts/`
- AI 活用方針 → `docs/ai-workflows/`
- エリア設計メモ → `docs/area/`

知見の保存は **再利用と引き継ぎのため**。一人で抱え込まない。

---

## 12. 承認プロセス（短縮版）

新規・大きめの作業を始めるときは、必ずこの順で進める：

1. **短い実装計画**（数行）を出す
2. ユーザーから承認を得る
3. 着手する
4. 完了後、**変更ファイル一覧・確認コマンド・確認 URL** を提示
5. コミットは明示指示があったときだけ
6. push は **別途明示指示**があったときだけ
7. 完了後、再利用できる知見は docs に保存

詳細は `CLAUDE.md §6` を参照。

## 13. このファイルの位置づけ

- このファイルは AI（Claude Code 含む）の自動的な行動を **抑止する側**のドキュメント
- 「AI を活用する」より「事故を起こさない」が優先
- 不明な点は **手を止めて人間に確認**する
- 「便利だから自動化する」より「安全だから手動を残す」を選ぶこともある

困ったとき・判断に迷ったときは、`CLAUDE.md §8` の優先順位：

1. ご遺族への配慮
2. 信頼感・地域密着
3. 問い合わせ動線への接続のなめらかさ
4. SEO / AIO
5. 実装の優雅さ
