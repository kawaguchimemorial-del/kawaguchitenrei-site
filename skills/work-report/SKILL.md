# Skill: サイト修正レポート記録手順

## 目的

川口典礼サイトに修正（コード・コンテンツ・設定・インフラ復旧）を行ったら、**毎回**その内容を社内レポートとして `docs/reports/` に HTML で残すための標準手順。
作業の経緯・原因・変更点・確認結果・今後のアクションを後から追えるようにし、引き継ぎと再発防止に使う。

> ユーザー方針（2026-06-05）：「サイトを直したときは、毎回レポートに残すこと」。
> レポートは **Web には公開しない**（`docs/` は Next.js の配信対象外。各 HTML に `noindex` 指定）。

---

## 適用範囲（レポートを残す対象）

以下のいずれかを実施したら、レポートを作成・追記する：

- サイトのソース修正（`app/**` / `components/**` / `lib/**` / `next.config.ts` / `public/images/**` など）
- SEO/AIO 改善（title / metaDescription / FAQ / JSON-LD / relatedLinks / 結論先出し / 内部リンク 等）
- リダイレクト・sitemap・robots の変更
- 障害対応・インフラ復旧（例：SEO ダッシュボードの refresh_token 失効復旧）
- 環境変数・デプロイ設定の変更を伴う対応（値そのものは記載しない）
- 分析のみで実変更がない場合も、調査結果が今後の判断材料になるならレポート化してよい

**適用外（レポート不要）**:
- ドキュメントのみの軽微な誤字修正
- 一時ファイル（`tmp/**`）だけの作業
- このレポート自体の作成・index 追記

---

## 配置と命名

- ディレクトリ：`docs/reports/`
- ファイル名：`YYYY-MM-DD-<英小文字ケバブの要約>.html`
  - 例：`2026-06-05-seo-dashboard-and-keyword-analysis.html`
  - 同日に複数あれば要約部分で区別する
- 一覧：`docs/reports/index.html` の先頭リストに**新しい順で1行追記**する

---

## 手順

1. 作業が一区切りしたら、本 Skill のテンプレートで HTML レポートを作成する
2. `docs/reports/index.html` のリストに当該レポートへのリンクを新しい順で追記する
3. 変更ファイル一覧（§18 の出力形式）にレポートと index も含めて提示する
4. `docs/**` は自走 push 可の範囲（CLAUDE.md §19.1）。push の要否は通常の運用ルールに従う（指示があれば commit→push、なければローカルに残す）

---

## レポート書式（必須セクション）

各 HTML は自己完結（インライン CSS）・日本語・`<meta name="robots" content="noindex,nofollow">` 必須。最低限つぎを含める：

1. **ヘッダー**：タイトル / 作成日（絶対日付）/ 対象データ期間（あれば）/ 担当
2. **サマリ**：今回の対応を箇条書きで（完了 / 提案・未着手 のタグ付け）
3. **背景・原因**：なぜ直したか。障害なら原因と根本要因
4. **変更内容**：何を・どのファイルで・どう変えたか
5. **確認結果**：`npm run build` の結果、静的生成ページ数の増減、その他確認
6. **今後のアクション**：残課題・次タスク・再測定予定（絶対日付で）

雛形は既存の `docs/reports/2026-06-05-seo-dashboard-and-keyword-analysis.html` を参照・流用してよい。

---

## 注意事項（厳守）

- **秘密情報を書かない**：トークン値・API キー・Webhook URL・`FORM_WEBHOOK_SECRET` 等は一切記載しない（CLAUDE.md §12）
- **個人情報を書かない**：氏名・電話・メール・住所・相談内容・故人/喪主名など（§12）
- **価格は §9 プラン正本のみ**。正本外の数字を推測で書かない（§14）
- **断定・煽り表現の禁止**（§11）。事実と確認済みの内容に限る
- レポートは社内記録。Web 非公開を崩さない（`public/` や `app/` に置かない・ルート化しない）
